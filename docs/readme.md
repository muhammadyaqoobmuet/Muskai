# Muskai — Text-to-Reels

Muskai is a self-hosted text-to-video studio. You describe a scene in one prompt, the API plans it into 5-second segments, each segment is generated by Alibaba's DashScope Wan models, and the segments are stitched with ffmpeg into a downloadable vertical reel. Finished generations can be published to a public explore feed with likes.

**Status journey:** `QUEUED → RUNNING → STITCHING → SUCCEEDED | FAILED`

**Ports at a glance**

| Service     | URL                        | Notes                                  |
| ----------- | -------------------------- | -------------------------------------- |
| Web (Next)  | http://localhost:3000      | Studio, library, explore               |
| API         | http://localhost:4000      | REST + static `/files` storage         |
| Postgres    | localhost:**5433**         | Docker maps host 5433 → container 5432 |

## Prerequisites

- Node.js 20+ (engines: `>=20`)
- Docker (for Postgres only)
- ffmpeg available on `PATH` (segment stitching runs in the API process)
- A DashScope API key (`DASHSCOPE_API_KEY`). The server still boots without one; generation requests then fail with a visible `DASHSCOPE_NOT_CONFIGURED`-style error.

## Quickstart

```bash
# 1. Start Postgres (host port 5433)
docker compose up -d

# 2. Configure the API — create apps/api/.env with at least:
DATABASE_URL=postgresql://muskai:muskai_dev@localhost:5433/muskai
DASHSCOPE_API_KEY=sk-xxxx            # your DashScope key
SESSION_SECRET=change-me-to-32-random-chars

# 3. Install and prepare the database
npm install
npm run setup    # builds @muskai/shared, prisma generate + db push

# 4. Run both apps
npm run dev      # api on :4000 + web on :3000
```

Open http://localhost:3000, create an account at `/signup`, and start generating.

## Data model (Prisma, 6 models)

- **User** — handle (unique), email (unique), scrypt-hashed `passwordHash`, `bio`.
- **Generation** — `prompt`, `mode` (`TEXT_TO_VIDEO`, `IMAGE_TO_VIDEO`, `KEYFRAMES`, `REFERENCE`, `EDIT`), `aspectRatio` (default `9:16`), 10-second target, status, `firstFrameUrl`/`lastFrameUrl`, `videoUrl`, `posterPath`, `errorCode`/`errorMessage`, unique `clientRequestId` for idempotent retries, `published` + `publishedAt` + `viewCount`.
- **Segment** — could be regenerated independently; `dashscopeTaskId`, `sourceFramePath`, `seg-N.mp4` output, `durationSec` 5, unique per generation index.
- **Like** — composite key `userId + generationId`.
- **ModelUsage** — hard quota observations per model (`quotaTotal`, `unitsObservedUsed`, `exhausted`).

## Pipeline

1. You land on `/studio`, type or select a template prompt, and pick a mode or let the planner choose defaults.
2. `POST /api/generations` inserts the row and kicks off a background job tracked by `runningJobs`.
3. The planner slices the prompt into 5-second segments and builds an image prompt per segment.
4. Each segment submits to DashScope (`wan2.2-t2v-plus`, `wan2.2-i2v-flash`, `wanx2.1-kf2v-plus`, or `wan2.2-vace-plus` depending on mode), poll-awaits completion, and the MP4 lands at `storage/<generationId>/seg-N.mp4`.
5. Chaining modes extract each segment's **last frame** to seed the next segment's image so motion continues across cuts.
6. ffmpeg concatenates `seg-N.mp4` into `<generationId>/final.mp4`, extracts a poster, and flips the status to `SUCCEEDED`.
7. The client polls `GET /api/generations/:id` and, on success, redirects to `/reel/[id]`. `Failed` generations surface `errorCode`/`errorMessage`.
8. Stall recovery: on boot the worker re-scans generations stuck in `RUNNING`/`STITCHING` and re-KICKS their polling (`POST /api/generations/:id/recover`, internal) rather than orphaning jobs.

A process restart mid-run surfaces `GENERATION_STALLED` on the next status check rather than a silent hang.

## Troubleshooting

| Symptom                                   | Fix                                                                                       |
| ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| `/api/generations` 500s mentioning ECONNREFUSED | Postgres is not up on 5433 — re-run `docker compose up -d`.                          |
| Generations fail instantly                 | `DASHSCOPE_API_KEY` unset, or the key's model quota ran out (see the `/api/models` catalogue). |
| `_generation_<id>.mp4` missing             | ffmpeg not found — ensure `ffmpeg` is on the API process' `PATH`.                         |
| Video files serve from index HTML          | You set a wrong value into `STORAGE_DIR` (it must be the web-visible `/files` base). Those live under `storage/<generationId>`. |
| Every job is `FAILED`                      | Use the `/api/models` response payload to pick a different capability model (there is a hard-fallback catalogue built in). |
| Port already in use                        | Kill previous `npm run dev`; both apps fail fast on `:3000` / `:4000` / `:5433`.          |
